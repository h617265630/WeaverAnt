# WeaverAnt

[English](README.md) | 简体中文

**以网页为核心交互界面的 AI 对话、项目管理与辅助开发工作空间。**

让对话变成一个可以浏览、编辑和持续开发的工作空间，而不只是一串需要不断翻阅的聊天记录。

> 当前是基于 React 与 Node.js 的本地优先 MVP。界面主要使用中文，部分位置仍沿用 **WB / WB Studio** 名称；项目正式名称为 WeaverAnt。

## 为什么不只使用聊天窗口？

传统聊天窗口适合提问，但当对话逐渐变长、任务逐渐复杂时，会出现一些问题：

- **重要信息难找。** 需求、结论、链接和代码说明散落在长对话中。
- **追问容易打断主线。** 针对某一段内容的讨论，与原来的话题混在一起。
- **回答不等于项目状态。** AI 给出方案，不代表它已经变成可管理的计划、任务和参考资料。
- **局部修改难描述。** 与其解释“标题下面第二张卡片”，不如直接选中那张卡片。
- **上下文分散。** 聊天、调研、项目管理和开发在不同工具中进行，需要反复搬运信息。

WeaverAnt 尝试另一种方式：**以生成的网页与结构化网页界面作为工作载体，让用户直接在页面中与 AI 交互、管理对话和推进项目。**

## WeaverAnt 是什么？

WeaverAnt 是一个交互式 AI 工作空间和开发助手。你可以从一个问题或想法开始，把知识整理为可操作的页面，再逐步进入项目规划与开发。

它连接本机的 **Codex 或 Claude Code**，调用其模型、Agent 和工具执行能力。WeaverAnt 本身提供界面、项目上下文与持久化记录，不是新的基础模型。

这里有两个不同的对象：

| 对象 | 用途 |
| --- | --- |
| **WB 工作空间** | 管理对话、调研、需求、方案、任务、资源和原始记录。 |
| **目标项目** | 真正要开发的软件或网站，拥有自己的代码目录和开发预览。 |

### “实时生成网页式交互”具体指什么？

产品方向是让 AI 生成的网页成为可以持续交互的工作环境。当前实现包含三个层次：

1. **实时结构化对话：** 回复逐步显示为标题、段落、列表、表格和代码块，不必等待完整回复或 HTML 文档生成后才能阅读。
2. **可编辑的管理页面：** 用户和 AI 工具可以更新内容模块、任务、链接和项目资料。AI 还可以提供专属 HTML 页面进行隔离展示；知识页面可以导出为独立 HTML。
3. **目标项目的交互预览：** 生成或导入的网页项目展示在开发窗口中。选中文字或页面区域，就能围绕该位置向 AI 发出局部指令。

**并不是每条回复都会生成一个新的独立 Web 应用。** 对话展示直接利用回复本身的结构，不额外调用模型重写摘要，也不会把聊天内容当作任意 HTML 或 JavaScript 执行。项目预览反映真实文件与构建产物，目前不会自动管理目标项目的开发服务或热更新。

## 快速开始

### 环境要求

- **Node.js 22.13 或更新版本**及 npm。
- 已安装并登录的本机 **Codex 或 Claude Code**，用于真实 AI 请求。
- 现代浏览器；自动化浏览器测试默认使用 Google Chrome。

不发送 AI 请求，也可以体验管理功能和内置示例。

### 安装与运行

```sh
git clone https://github.com/h617265630/WeaverAnt.git
cd WeaverAnt
npm ci
npm start
```

打开 **http://127.0.0.1:4317**。

保持终端运行，按 **Ctrl+C** 停止服务。启动命令会构建 WeaverAnt 和内置示例，再启动本地服务；不会自动构建导入的目标项目。

- **4317：** 工作空间主界面。
- **4318：** 用于嵌入目标项目的独立预览源。

### 连接 AI

在主侧边栏打开「连接与设置」：

1. 选择 Codex 或 Claude Code 作为新会话的默认提供方。
2. 检查本地连接；如有需要，先在对应工具中完成登录。
3. 返回 WeaverAnt 发送消息。

WeaverAnt 会尝试发现本机可执行程序，包括支持的 VS Code 扩展安装位置。Claude Code 也支持在设置中填写程序路径。自动发现失败时，可以启动时指定：

```sh
WB_CODEX_BIN="/完整路径/codex" npm start
# 或：
WB_CLAUDE_BIN="/完整路径/claude" npm start
```

已有会话保持原来的 AI，修改默认设置不会迁移旧会话。真实请求会使用对应账户的额度；这些本地适配器不要求在 WeaverAnt 中额外填写模型 API Key。

## 用户使用流程

### 1. 开始对话或任务

在入口页选择聊天或任务，发送第一条消息。此时才创建专属工作空间和侧边栏历史条目；仅打开空白聊天不会产生记录。

例如：

> 帮我调研一个个人记账工具，比较可能的使用流程，确定最小可用的第一版。

回复会实时进入结构化阅读区域。主对话、追问和辅助资料分别展示，不必全部挤在同一条长消息流中。

### 2. 针对某段内容展开讨论

选中已完成消息中的文字，会在附近出现 **select-dock**。你可以针对选段提问、请求相关资源，或保存为重点。

后续回复展示在独立区域，并通过标签与原文关联。还可以继续选中子对话内容，逐层展开新的讨论，保留主线。

主输入框 **float-dock** 固定在对话区域下方。**Enter** 发送，**Shift+Enter** 换行。界面默认跟随流式回复；向上翻看历史时暂停跟随。

### 3. 整理知识与资料

在「资料与管理」中查看内容模块、资源、重点和原始记录：

- 已保存消息及支持的工具结果中的链接，会被归集、去重并保留来源。
- 保存的选段可以在「重点」中查看。
- 可以直接编辑管理内容，也可以搜索已有资料，不需要额外模型调用。
- 原始消息继续保留，不会被摘要替代。
- 知识页面可以导出为独立 HTML，不运行 WeaverAnt 服务也能查看。

资源不会自动下载或验证可信度。结构化整理依赖用户编辑或 AI 工具调用，并不是每条消息都会自动生成一个模块。联网搜索能力取决于当前 AI 可用的工具。

### 4. 从想法进入项目

点击侧边栏「项目」旁的 **+**，或在对话管理页点击「启动项目」，选择：

- **先规划：** 明确第一版范围、开发规范和参考项目。
- **直接开始：** 进入开发窗口，边做边完善需求。

在「项目规划」中，可以选择常用规范或自行填写技术栈、视觉风格、可访问性、测试要求和依赖约束。记录参考项目时，也可以说明希望借鉴什么、不照搬什么。

保存的规划内容会随之后的项目开发请求提供给 AI，也可以随时返回调整。

### 5. 在页面中开发

开发窗口结合了目标项目预览、固定的全局聊天框，以及 AI 汇报、Todo、文件目录等面板。

通过全局聊天框提出整体需求：

> 按照已保存的开发规范，实现记账概览和添加收支的表单。

如果只想修改局部：

1. 选中文字、使用「点选局部」，或双击支持的页面区域。
2. 必要时通过父级、子级和 DOM 层级路径调整选区。
3. 在局部 select-dock 输入修改指令。
4. 在左侧「AI 汇报」查看结果。

选中文字、选择器、HTML 片段及可用的源码标记会作为上下文传给 AI。AI 修改真实项目文件；选择浮层由预览环境注入，不会写入最终交付的应用。

select-dock 还提供 **AI 建议、配色卡和 UI 组件方案**。配色与组件卡是内置方案，不是动态生成的推荐。点击方案只会填入输入框，确认发送后才执行 AI 请求；AI 分析结果仍展示在左侧汇报区。

### 6. 继续开发已有本地项目

在主侧边栏点击「打开本地 Web 项目」。macOS 可以使用系统文件夹选择器，也可以手动填写绝对路径。选择包含 `index.html`、`dist/index.html` 或 `package.json` 的项目根目录。

- 绑定原目录，不复制项目。
- 打开时不会安装依赖、执行项目脚本或自动调用 AI。
- 再次打开同一个实际目录，会沿用已有 WB 工作空间。
- 后续开发指令会作用于原文件，建议提前使用 Git 或其他方式备份。

**导入成功不代表任意项目都能立即预览。** 当前支持静态 HTML 和兼容的构建产物；全栈应用与根路径资源还需要额外适配，见下方限制说明。

### 不消耗模型额度的体验入口

打开「全部项目」→「体验记账 App 示例」。内置示例是真实 React 页面，包含示例交易数据。

浏览页面、选择区域和使用管理功能不需要模型请求；发送聊天消息则会使用真实账户额度。

## 项目管理与本地数据

- **Todo：** 添加、编辑、完成、筛选和删除任务；管理页与开发页共用同一份任务数据。
- **文件目录：** 展示已索引的项目文件；文件变化不自动等于任务完成。
- **原始记录：** 保存 WB 创建的对话和协议事件；不会自动读取 VS Code 私有历史，可手动粘贴导入。
- **同步设置：** 按分类选择自动或手动处理；原始会话保存独立于摘要同步。
- **管理版本：** 恢复管理内容，不回滚项目代码。版本面板**不是 Git**。

| 位置 | 内容 |
| --- | --- |
| `.wb-data/workspace.sqlite` | 工作空间、模块、对话、记录、事件和管理版本。 |
| `.wb-data/projects/<project-id>/app/` | 新目标项目的默认目录。 |
| 导入项目的原始目录 | 绑定项目的真实文件。 |

备份 `.wb-data` 前请停止服务；外部绑定目录需要另行备份。运行时工作空间数据不会提交到本仓库。

## 技术结构

```text
聊天 / 任务
  → 结构化网页工作空间
  → 项目规划与资料
  → 目标项目预览 + 全局 / 局部指令
  → 本地 Agent 桥接 → Codex 或 Claude Code → 项目文件
                   ↘ WB MCP 工具 → 工作空间更新
```

| 层次 | 主要代码 |
| --- | --- |
| React 工作空间与项目界面 | `src/` |
| 本地 API、预览、文件同步 | `server/index.mjs` |
| AI 路由与适配器 | `server/agents.mjs`、`server/codex.mjs`、`server/claude.mjs` |
| SQLite 内容与版本存储 | `server/store.mjs` |
| AI 整理工作空间的工具 | `server/mcp.mjs` |
| 预览中的选区与层级导航 | `public/overlay.js` |

普通静态网页无法启动 Agent 进程、持续访问项目文件或处理开发审批，因此完整功能需要 Node 本地服务。构建后的主界面不依赖 Vite 开发服务器运行。

## 配置与开发

```sh
# 修改本地端口。
PORT=4417 WB_PREVIEW_PORT=4418 npm start

# 使用其他工作空间数据目录。
WB_DATA_DIR="/完整路径/工作空间数据" npm start

# 开发 WeaverAnt 自身的前端。
npm run dev
```

开发命令会在前端文件变化后重新构建，刷新浏览器查看效果；服务端代码修改后需要重启。这不会启动目标项目的开发服务器。不要同时运行两个实例操作同一个工作空间数据库。

内置桥接会为自己的 Agent 进程提供 WB MCP 配置，无需修改全局配置。若希望从外部 Codex 客户端操作 WB，可以运行 `npm run config`，审核输出后添加到对应客户端。两端必须指向同一个数据目录；该辅助命令输出仓库默认 `.wb-data` 路径，使用自定义目录时需要调整。

## 安全说明

两个服务均绑定 `127.0.0.1`。管理 API 检查本地令牌、Host 和 Origin，目标预览使用独立源。本项目是单用户本地工具，不是面向恶意项目的强隔离沙箱，也不是可直接暴露到公网的多租户系统。

AI 请求可能读取文件、修改代码、执行命令、联网并消耗账户额度。运行不熟悉的项目脚本前请先审查。

Codex 的操作审批会在界面中展示，不会自动批准。Claude Code 的交互式审批尚未桥接，缺少权限的操作可能被拒绝；适配器不会使用绕过权限的参数。

## 当前限制

- **根路径资源预览：** 引用 `/assets/...` 的构建产物可能白屏，因为当前预览位于 `/app/<project-id>/` 下。相对资源路径，例如 Vite 配置 `base: './'` 后生成的资源，更适合当前结构；应用路由和 API 地址仍可能需要单独处理。自动路径适配尚未完成。
- **不自动运行目标项目：** 导入不会启动 Vite、后端或数据库，暂不自动编排、代理服务端渲染与全栈服务。
- **不保证 DOM 到源码的精确映射：** 选区提供上下文，不等同于源码编辑器定位。稳定的 `data-ai-id` 与 `data-ai-source` 标记可以辅助定位。
- **同一项目同时执行一个 AI 任务：** 全局与局部请求共用项目锁，避免并发修改。
- **自定义 HTML 是展示层：** 不自动获得管理数据写权限，修改通过原生编辑器或 MCP 工具完成。
- **本地优先 MVP：** 暂无团队权限与集成式云端部署。

## 检查与测试

```sh
npm run check
npm run build
npm test
npm run test:browser
```

浏览器测试按 `playwright.config.mjs` 使用 Google Chrome。自动化测试使用独立临时工作空间和模拟 Agent，不消耗真实模型额度，覆盖对话、局部交互、项目流程、持久化和本地导入。

可选执行 `node scripts/smoke-codex.mjs` 进行真实 Codex 冒烟测试。与模拟测试不同，它会调用本机 Agent，可能消耗账户额度。
